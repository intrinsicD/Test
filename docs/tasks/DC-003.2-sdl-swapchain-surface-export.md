## Description

### Problem Statement
Completing `DC-003` requires the SDL backend to export graphics surfaces that match the GLFW implementation and to participate in the runtime's deterministic backend selection. After `DC-003.1` introduces the native window lifecycle and event pump, the remaining gap is plumbing swapchain surface handles for Vulkan/OpenGL and ensuring that runtime overrides and fallback logic select SDL (or demote cleanly) without regressions. Without this work the rendering module cannot exercise SDL surfaces, CI cannot validate backend selection order, and downstream initiatives (visibility culling benchmarks, tooling UX) remain blocked on GLFW-only execution paths.

### Proposed Solution
Extend the SDL backend to construct swapchain surfaces compatible with the rendering schedulers and to report capability failures through structured errors. Update the backend selection pipeline to evaluate SDL availability before falling back to GLFW/mock, mirroring the ordering documented in the platform README. Harden configuration presets and CI automation so SDL coverage executes deterministically, and surface telemetry for selection outcomes. Update documentation and task records to capture the new fallback behaviour and developer setup guidance.

### Success Criteria
- Rendering backends obtain valid Vulkan/OpenGL surfaces from the SDL window implementation with parity to GLFW.
- Backend selection honours runtime overrides, prioritises SDL when requested, and deterministically demotes to GLFW/mock with structured telemetry.
- CI executes at least one preset that builds and runs with SDL swapchain surfaces enabled, exercising rendering + runtime integration tests.
- Documentation describes setup, fallback ordering, and telemetry expectations for SDL swapchain usage.

## Test Plan

### Unit Tests
```cpp
TEST(SdlWindowBackend, ExportsVulkanSurface) {
    auto window = make_sdl_window(WindowConfig{/* ... enable Vulkan */});
    auto surface = window->create_swapchain_surface(RenderBackend::Vulkan);
    ASSERT_TRUE(surface);
    EXPECT_TRUE(surface->is_valid());
}

TEST(SdlWindowBackend, FallsBackWhenSdlUnavailable) {
    ScopedSdlDisable guard;
    auto backend = select_window_backend(WindowSelectionRequest{.preferred = Backend::SDL});
    EXPECT_EQ(backend.type(), Backend::Mock);
    EXPECT_THAT(backend.telemetry().reason, Eq("SDLUnavailable"));
}
```

### Integration Tests
- Extend runtime integration suite to render a frame using SDL surfaces for Vulkan/OpenGL and assert swapchain validity + telemetry counters.
- Add cross-backend fallback integration test verifying override order (SDL preferred, falls back to GLFW, then Mock) with deterministic logging.

## Implementation Notes

### Design Considerations
- Reuse GLFW swapchain helper abstractions to avoid divergence in rendering pipelines.
- Encapsulate SDL/Vulkan surface creation behind version-specific helpers to support SDL2/SDL3 differences.
- Instrument backend selection to publish structured telemetry consumed by diagnostics tooling.

### Risks & Mitigations
| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| SDL Vulkan extensions unavailable on CI runners | Medium | High | Install Vulkan-enabled SDL packages and add guard rails that demote gracefully with telemetry. |
| Backend selection regressions affecting GLFW users | Medium | Medium | Add integration tests covering all fallback permutations; retain previous ordering as baseline. |
| Divergent SDL2 vs SDL3 surface APIs | Medium | Medium | Introduce abstraction layer with compile-time/version detection and shared tests. |

### Alternative Approaches
1. **Defer swapchain support until SDL3 stabilises**: rejected—blocks roadmap initiative and downstream rendering tasks.
2. **Use GLFW-created surfaces behind SDL window handles**: rejected—breaks abstraction layering and fails parity requirement.
