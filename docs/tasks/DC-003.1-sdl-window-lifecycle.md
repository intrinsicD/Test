## Description

### Problem Statement
`DC-003` cannot progress until the SDL backend produces native windows and deterministic events. The current `sdl_window.cpp` stub mirrors the GLFW shape but never calls into SDL, leaving runtime feature work and CI SDL coverage blocked. We must replace the stub with a production-ready implementation that satisfies the lifecycle, event, and telemetry requirements captured in `docs/modules/platform/SDL_BACKEND_CHECKLIST.md`.

### Proposed Solution
Implement the SDL window backend on top of the existing `Window` abstraction. Add native creation/destruction, translate SDL events into the engine queue with deterministic ordering, and surface capability failures through structured errors and telemetry. Gate behaviour behind build flags so the mock backend remains available when SDL packages are absent. Extend runtime smoke tests to exercise SDL selection via environment overrides.

### Success Criteria
- Native SDL window lifecycle executes without leaks across Linux, Windows, and macOS builds configured with SDL.
- Event pump translates keyboard, mouse, controller, and window events into engine events in a deterministic sequence that matches GLFW behaviour for equivalent input streams.
- Telemetry and logging expose SDL initialization/version metadata and downgrade-to-mock behaviour when SDL prerequisites fail.
- Runtime integration test runs with `ENGINE_PLATFORM_WINDOW_BACKEND=sdl` pass, demonstrating compatibility with the rendering swapchain handoff.

## Implementation Notes

### Design Considerations
- Mirror GLFW backend abstractions to preserve backend-agnostic usage across runtime/rendering.
- Buffer SDL events before publishing to guarantee deterministic ordering even when SDL dispatches per-subsystem.
- Surface SDL version/build metadata through telemetry for troubleshooting.

### Risks & Mitigations
| Risk | Likelihood | Impact | Mitigation |
|------|------------|--------|------------|
| CI builders lack SDL packages | High | Medium | Add installation steps to presets and document fallback to mock backend when unavailable. |
| SDL 2 vs SDL 3 API differences | Medium | Medium | Introduce adapter helpers hidden behind compile-time switches; document supported versions. |
| Event determinism drifts from GLFW | Medium | High | Use recorded input traces and cross-compare sequences between backends in tests. |

### Alternative Approaches
1. **Maintain stub implementation**: rejected—fails roadmap goals and leaves SDL path untested.
2. **Adopt third-party backend abstraction**: rejected—introduces new dependency layer and diverges from established windowing architecture.
